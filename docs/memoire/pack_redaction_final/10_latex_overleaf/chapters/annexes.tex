\section{Regles de prudence}
Pour toute lecture des resultats, les regles suivantes doivent etre conservees :
\begin{itemize}
  \item les anomalies non supervisees sont des anomalies candidates ;
  \item la baseline fail2ban-like n'est pas une execution officielle de fail2ban ;
  \item Wazuh/OSSEC restent des references operationnelles plus matures ;
  \item la distribution multi-machine stricte est une perspective ;
  \item la memoire adaptative est une capitalisation auditable des historiques et feedbacks ;
  \item l'auto-apprentissage continu avec reentrainement controle reste une extension future.
\end{itemize}

\section{Exemple de lecture scientifique des resultats}
Une lecture rigoureuse des resultats doit suivre quatre etapes. La premiere consiste a identifier le type de donnees : labelisees, non labelisees, synthetiques ou issues d'un outil externe. La deuxieme consiste a choisir la metrique adaptee. Un F1-score est pertinent pour une source labelisee, mais il ne l'est pas toujours pour un export non supervise. La troisieme consiste a relier la valeur a une preuve. La quatrieme consiste a formuler une conclusion proportionnee.

Par exemple, le resultat Wazuh ne doit pas etre formule comme une detection de 3 676 attaques. La formulation correcte est que le prototype a traite 122 563 evenements et produit 3 676 anomalies candidates selon le detecteur non supervise applique. Cette nuance est importante car elle distingue le signal algorithmique de la validation securite.
